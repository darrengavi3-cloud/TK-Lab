# 觀史台人物誌重構 · P1a 核心與只讀預覽

基線：`c2cef1ce3a21eb503ae0c5c7e5415173810cc39e`。本變更不改寫任何既有部署事實；不是整個人物誌資料庫已遷移完成的宣告。

## 本批已實作

在 `domain/prosopography/` 建立獨立、可測試的研究模型，並以 `server/prosopography-preview.ts` 接入既有目錄修訂的只讀接口。

| 結構 | 語義 |
| --- | --- |
| `OfficeTenure` | 一次任職的穩定識別；同官復任不自動合併 |
| `CareerEvent` | 授官、就任、轉任、免官、復拜等事件；一次事件可涉及多個職任 |
| `HistoricalTime` | 一項年代說法的最早／最晚界限；不等於持續任期 |
| `Claim` | 實任狀態、始任、終任、某年見任、連續性或事件年代的具體說法 |
| `EvidenceLink` | 以 ID、修訂序號及 SHA-256 固定的來源；區分支持、反證與尚未分類的舊異文 |
| `FactualConflict` | 同一主體、同一問題的史事異說組 |
| `TextualVariant` | 指定校勘位置與不同固定版本讀法；讀法須逐字見於所引原文 |

事件日期不能直接填入任期起訖。被俘、投降、死亡及下一次任官不會自動結束上一職任。相對次序可以沒有年份；循環或失效引用會被拒絕。

### 在任查詢的保守口徑

`presenceInYear`／`personPresenceInYear` 回傳：`attested`、`continuous`、`possible`、`unknown`、`not-held`、`outside` 或 `excluded`。

`attested` 只表示該年某時曾實任，不表示全年在任。兩個確定端點不能單獨證成中間各年連續在任；`continuous` 另需被採用且有證據的連續任期說法。確定區間採取「最晚始任—最早終任」的保守交集。推定、待考、存疑及未解決的異說不能輸出 `definite: true`。

採用的始終任與見任說法互不相容時，保留全部說法並回傳警示，不刪除材料或拼出虛假任期。未就任、追贈可作為真實經歷保留，但不計入實任。顯示範圍、整理流程與史實判斷仍分開。

### 原始記錄轉換

只讀轉換 `legacyResearchGraph` 保留既有 Person/Appointment ID、原官名、政權、轄區、性質、年代文字、原始審定與來源修訂。只有已明確登記 `duplicateOf` 且目標吻合的記錄才合併為同一任職；每一原始出處仍保留自己的說法與引用。相似姓名或相同官名不觸發合併。

舊 `date.startYear/endYear` 一律先作為 `legacy-record` 原樣保留，不自動解釋為任期、單次事件或見任。新結構化說法初始為待解譯，不能承襲舊記錄的核定。舊異文標記只轉為 `unclassified-variant`，不憑標記生成文本校勘或史事爭議。

引文按被引用的確切修訂讀取，而不是改用最新版本。找不到舊版、摘要或內容不符、引用版本晚於所選快照均報錯。原文空白、異體字、原注及節引／全文範圍不自動正規化。預覽可供擁有者檢視私有原文，不使其變成閱讀端內容。

## 已接入的後台 API

兩個路由均位於既有 `owner()` 權限檢查之後；POST 仍須同源 `Origin`、`Sec-Fetch-Site` 及 `X-Catalogue-Request: 1`。權限識別沿用既有可信 Sites dispatch 邊界，不接受 body 提供的擁有者身份。

```text
GET /api/admin/prosopography?personId=<既有ID>&watermark=<提交序號>&year=<公元年>
POST /api/admin/prosopography/validate
```

GET 的 `watermark` 和 `year` 可省略。前者省略時固定到本次讀取的最新目錄提交；後者省略時只回傳研究預覽，不查某年在任。HEAD 不回傳正文。

POST body：

```json
{"graph": "以 GET 返回的 graph 物件取代此說明字串", "watermark": 3, "year": 203}
```

POST 接受修改後的研究圖，校驗結構、精確版本引用及年代語義，**不保存修改**。範例中的 `3`、`203` 只是參數形式；實際提交序號與人物 ID 必須取自目錄。本批尚無此研究圖的編輯表單。

所有成功結果明示：

```json
{"structurallyValid": true, "historicalReviewPerformed": false, "persisted": false, "published": false}
```

返回內容包含固定人物修訂、研究圖、實際引用原文、警示、可選在任結果與內容摘要。同一快照、資料及查詢可重現同一摘要；摘要不是人工史學核定、發布批准或部署回執。

`ResearchReadStore` 只有 `watermark`、`snapshot`、`revision` 三種讀取能力；研究服務沒有資料庫／物件儲存寫入、發布或部署能力。既有擁有者首次綁定流程不作變更。路由使用 `Cache-Control: no-store`；閱讀端路由、DTO 白名單及既有快照均不接收新研究物件。

批次上限：單人最多 1000 個任職、1000 個事件、5000 項說法、10000 條證據，以及最多 2000 個不同引用修訂；超出時明確拒絕，不截斷材料。

## 還沒有完成的工作與後續接管

本批是第一階段的 **P1a 模型＋證據校驗＋只讀對照預覽**，不是完整 P1 任職資料接管。

下一批 P1b 才增加關係式持久化、不可變研究修訂與並行編輯保護、具名採擇／覆核操作、批次匯入與後台表單，以及明確的新研究發布投影。保存端必須重新驗證引用與版本、核定新內容的精確摘要；不能直接把預覽 JSON 視作已批准發布。

官職制度版本、史料作品／版本／實物見證及轉引鏈、政區分期、封爵食邑、察舉徵辟與九品評品、宗族社會關係、群體事件參與分析，仍是後續領域；本批只提供可銜接的核心結構，未假裝完成其資料表、研究考證或查詢。

未改動 `domain/catalogue.ts`、原任官閱讀判定、原發布策略、`db/`、`drizzle/`、`atlas/`、閱讀介面、資料集、R2 內容及部署回執。既有閱讀端年代邏輯在本批保持原狀；研究預覽中的保守判定尚未取代它。撤回本批程式無須資料回滾，因為不存在研究資料寫入或模式遷移。
