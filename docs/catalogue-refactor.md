# 資料核心重構：第一批實作與交接

使用方式已確定：擁有者在管理後台編輯、匯入、修訂並統一控制發布。

## 本分支已實作的程式

- domain/catalogue.ts：人物、任官、史料的 TypeScript 契約與執行時驗證；身份、史實、整理、顯示各自獨立。原始年代、未知端點、推定依據、排除原因及固定引用修訂保留。
- domain/revisions.ts：修訂前置判斷、版本衝突、精確內容重新審定、固定提交序號快照，以及原檔＋映射＋匯入器版本的冪等身份。這些是無儲存副作用的規則函式，尚不是資料庫持久化服務。
- domain/publication.ts：明確的讀者欄位允許清單、候選與已核查詢、重複互證合併、程式／資料／政策／資產候選摘要、精確預覽確認與部署回執匹配。回執匹配函式不會呼叫 Sites，也不會生成部署成功紀錄。
- importers/legacy-atlas/index.mjs：現行來源與歷次審定的唯讀遷移器。保存全部輸入原始 UTF-8 位元組、SHA-256、穩定 ID、來源全文與舊讀者投影；保留排除記錄，不將 suppressed 一律翻成錯誤。人物欄位的完整研究資料仍在原始登錄檔中，不宣稱已轉為全部可編輯欄位。
- tests/catalogue-*.test.mjs：史實狀態、年代、同名身份、引用、重複互證、修訂衝突、候選摘要與基線完整性。既有 test:built 會一併執行；也可執行 npm run test:catalogue。

## 實際執行狀態

這是重構草稿，**沒有可用的管理後台，沒有資料庫寫入或新部署**。取得源碼及安裝依賴後，本次工作環境回報 environment_offline；本地檔案寫入、建置、預覽與 Sites 發布因此不可用。程式改由 GitHub 工具保存為獨立分支，實際 CI 結果以該 PR 的檢查為準。

第 43 版 R1 部署、V86 資料與 owner-only 權限維持原紀錄。Sumi-OCR 未重新引入。此分支不開通 D1／R2、不放寬 Worker 的 GET／HEAD 門禁，也不切換資料權威。

## 唯讀遷移的使用與邊界

執行 npm run migrate:shadow 只輸出核對報告。完整候選可寫入忽略的工作目錄：

~~~sh
node importers/legacy-atlas/index.mjs work/migration/v86-shadow.json
~~~

候選含研究資料，只供管理與遷移。不可複製到 public、讀者包或公開物件。輸出拒絕覆蓋既有檔案；原始 atlas/ 不變。

固定基線為 TK-Lab@7b8d03990b6b72b4d62bf93f2a39aaeb9367ebd2。當前讀者 2,074 人，任官 851 條（已核 263、待核 507、存疑 2、排除 79）；這些只約束此次遷移測試。測試同時核對 ID 集合、全部輸入位元組與原讀者內容，不只比較總數。

report.unresolvedReferences 明列無法在保留人物中找到的任官引用；不造人、不丟記錄、不自動按姓名合併。正式匯入必須先處理此清單及完整域內驗證。未知年代確定性保留 unknown，不能由「任官已核」推成「起訖年確定」。原有讀者快照保持完整，不以新投影替換它。

其他領域（金石、封爵、官制、州鎮、府署、戰事、食貨、形勢圖）繼續使用 atlas；本次沒有將它們誤列為已遷移。裝置上未提交的 IndexedDB 工作資料也尚未匯出與比對。

## 恢復執行後的次序

1. 同步本分支與最新 main，讀取現有 Site，重新建立可用的本地建置及預覽。
2. 建立 D1 專用資料表、外鍵、不可變修訂與提交序號；生成及核對正式 Drizzle 遷移。以資料庫事務再次核對版本，不把純函式檢查當作併發鎖。
3. 建立可信 Sites 身份的擁有者授權、來源／CSRF 檢查與明確 API 方法白名單；在隔離環境驗證偽造身份、越權、跨分頁衝突、重試和整批提交。
4. 以私密 R2 保存原檔和發布包，接通人物—任官—史料後台、Excel／CSV／JSON 預覽、來源版本選擇及修訂比較；沿用 Element Plus 與現有主題。
5. 為舊閱讀端建立相容輸出並逐項對比，再接候選預覽、確認、真正部署及回執回填。網頁內部署入口須先驗證平台支持，不能把 ChatGPT 工具當網頁 API。
6. 完成備份還原及發布回退，核對其他領域覆蓋後才切換寫入權威、退役舊流程；實機、鍵盤、200% 縮放驗收各自留證據。

完整後台與六階段重構尚未完成；本 PR 的合併或 CI 成功均不代表管理功能已上線。
