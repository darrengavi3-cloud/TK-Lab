# 管理後台一期：資料核心、修訂與內容發布

擁有者在 `/admin` 編輯人物、任官與引用史料，保存工作資料後，從發布中心預覽並統一發布。程式採用現有 Vue／Element Plus、TypeScript 領域模組、D1 及私密 R2。第一期已交付這條可用流程；第二次交付增加[任官閱讀關聯](catalogue-reader-links.md)，其他領域尚未全面遷移。

## 使用流程

1. 以站點擁有者帳戶登入，從閱讀頁「設定 → 資料管理」或 `/admin` 進入。
2. 首次按「載入既有資料」。服務端核验內置基線摘要，原檔保存後分段暫存，最後一次性提交。中途關閉可以繼續；相同包與映射不重複新增。初始化不發布新閱讀內容。
3. 在資料工作台／史料庫編輯。史實判斷、整理進度、讀者可見性各自獨立；新資料預設待核及後台可見。已核內容修改須重新確認。史料的原文換行、原注、異文及底本版本保留；引用固定到具體修訂。
4. 匯入 UTF-8 CSV、單工作表 Excel 或原生 JSON：保存原檔、對應欄位、查看新增／修訂及錯誤，再提交整批。未對應欄位留在原檔，須明確確認。完整預覽可下載。
5. 建立發布候選，打開實際候選閱讀頁核對，再確認「發布閱讀內容」。舊候選固定原資料，不會隨後續保存改變。發布失敗保留上一版，切回已發布版本不抹除工作修訂。

## 程式責任

- `domain/`：型別、年代／身份／證據驗證、欄位允許清單、不可變修訂、摘要及確認契約。
- `server/catalogue-service.ts`：D1 版本條件更新、批次事務、衝突、冪等保存及固定提交快照。
- `server/import-service.ts`、`bootstrap-service.ts`：私密原檔、格式／映射檢查、可恢復暫存及一次性基線。
- `server/publication-service.ts`：固定人物／任官／生平投影、引用版本、清單摘要、R2 快照及原子切換。
- `server/authorization.ts`、`admin-router.ts`：每次後台請求核驗可信 Sites 身份，明確 owner、Origin 及操作來源检查；其他讀者路徑繼續拒絕寫入。
- `server/backup-service.ts`、`scripts/restore-catalogue.mjs`：一致時間點備份、原檔／發布產物核驗及空環境還原材料。
- `admin/`：六個後台入口、表單、草稿恢復、修訂比較、匯入與發布。
- `importers/legacy-atlas/`：無寫入副作用的完整遷移與核對。

D1 遷移只含結構。基線封包編譯為私密 Worker 模組，不放在 `public/`，只可經已授權的初始化路徑處理。生產身份第一次以指定 owner 帳戶登入後固定到該 Site 的穩定 user ID；普通請求不得指定操作者。開發 fixture 僅在 Vite serve 與忽略檔存在時啟用，正式 build 不含 fixture 授權配置。

## 三種版本分開

| 標識 | 記錄位置 | 含義 |
| --- | --- | --- |
| V86／R1 | 原資料與產品回執 | 遷移來源及讀者行為基線 |
| 工作提交／閱讀快照 | D1 commits、releases、publication_events | 固定資料修訂、被引用原文修訂、政策、程式內容摘要、資產摘要及實際投影檔 |
| Sites 部署 | 獨立部署回執 | 真正更新網站程式的版號、推送源碼 SHA、打包摘要與部署完成時間 |

後台發布的是運行中應用的閱讀內容，D1 原子指標切換成功後才顯示已發布；它不呼叫或假造 Sites 部署。程式更新另走原有受控 Sites 流程。候選預覽與發布使用相同 R2 位元組並核驗摘要；程式／資產更新後舊候選必須重建，已發布資料可在相同 readerContract 下回退。跨不相容程式版本的回退必須搭配對應 Sites 程式版本，不能只切資料。

第 43 版 R1 是 2026-09-12 的歷史部署，原回執不改写。本期是否已上線、最新 Sites 版號及源碼，以 CURRENT-STATE.md 與獨立回執為準。

## 備份與還原

在系統設定下載 gzip NDJSON 備份。D1 各表在同一批次讀取中固定；R2 原檔、匯入暫存、讀者基線及發布產物按摘要逐一封裝，含完成標記。授權設定不帶到另一個站點。

```sh
node scripts/restore-catalogue.mjs BACKUP.ndjson.gz work/restore-new
```

此命令先檢查完整性、修訂摘要、原檔摘要、發布清單和活動版本，再產生 `data.sql`、`objects/` 與核驗清單；目錄已存在便拒絕覆蓋。還原到新空 D1／R2：先套用本版 Drizzle 結構，再執行資料 SQL、按原 key 匯入物件，最後驗證外鍵、修訂數、發布候選摘要及讀者預覽。正式資料庫切換須另留備份與切換回執；此工具不直接覆寫線上資料。

自動化還原演練使用真正的 Miniflare D1／R2：重建全部表與物件，檢查外鍵，核對修訂歷史，重新產生候選並比較摘要，驗證原活動版本仍可讀。
