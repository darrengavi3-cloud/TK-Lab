# 研究案卷：首轮整合

日期：2026-10-02。此文记录代码行为；不代表云端部署完成。

## 目标与来源

将人物、任职、事件、说法和固定版本史料连成可保存的私人研究案卷。沿用 PR #20 的 ResearchGraph、只读校验和不可变修订日志，整合 PR #28 的当前主线校准与共享分页。PR #21、#22 的平行模型没有合并；阅读端的既有核定、发布和权限规则保持原有所有权。

业务依据：`domain/prosopography/types.ts`、`validate.ts`、`journal.ts`、`server/research-preview.ts`、`server/research-journal.ts`；权限依据 `server/authorization.ts`。设计入口为根目录 `DESIGN.md` 与 `atlas/UX-CONTRACT.md`。

## 已实现的工作流

1. 从后台「研究案卷」按稳定人物 ID 打开；列表支持分页、明确搜索、IME 与 URL 恢复。
2. 事件编年分别保留原纪年、数值检索上下限、直接记载／推论、状态、理由与支持材料。一个事件可以有多条纪年说法；导入不会自动采用日期、建立任职或连续任期。
3. 任职显示旧记录与研究采择。按年查询复用现有证据规则，未知不是无官，某年见任不是整年在任。
4. 最多三份固定版本材料并读；其余材料与文字异文仍可完整展开。校验结果返回被核对的源修订，不能用最新版文字替代旧引文。
5. 保存新增不可变研究修订。含已核／采择的内容须确认本稿；摘要由服务端重新核验。失败保留输入，回执丢失后的重试复用同一操作 ID。
6. 并发冲突同时保留本稿和服务器稿，逐项选择后显式采用新基底。恢复历史会成为新草稿，保存后新增修订。
7. 导出 CSV 编年表、可打印 HTML 完整案卷和 JSON 草稿。CSV 对表格公式前缀做防护；HTML 和 JSON 保留原文。未保存草稿在导出中明确标记，JSON 保留原始预览与当前研究图。

## 材料包

`guanshitai-research-materials-1` 是传输格式，不是另一套数据库。`domain/prosopography/workspace.ts` 定义并验证完整格式。包由原文件摘要、人物名、Source 记录及事件候选组成。Source ID 包含原文件 SHA-256；每条纪年显式引用包内材料。1 MiB 文件限制；每包最多150份材料、150条事件，每次校验最多200个固定来源修订。

导入前必须由用户确认与当前人物的对应。通用原档导入 API 保存材料为私有待核 Source；案卷仍需另行保存。已有同 ID 的不同材料不被覆盖。材料导入采用既有分段暂存、原子提交和幂等重试；若材料提交后案卷校验失败，会保留批次并明确说明，不能将两步描述为同一个事务。

本轮将一份私人工作本转换为45条事件、47条纪年说法、59份材料，其中6份逐格保留完整原表。原 Excel 的1074个非空单元格逐项核对，原文件摘要未变。私人工作本及材料包不提交至公共仓库；仓库中的测试全部使用合成材料。材料包导入仍需在用户的私有站点中明确选择人物。

## 边界与后续

- 首轮提供事件表单和现有任职阅读；完整任期采择、反证及文字异文仍使用进阶研究图编辑。后续可逐步增加专门表单。
- 未自动做史实核定、同名合并、年度空缺填补或无证据的相对顺序补全；用户自行输入的数值也必须通过服务端规则。
- 一个人物目前对应一个修订案卷；多人专题案卷、跨案卷分析、全文检索和研究成果发布可作为后续增量。
- JSON 恢复依赖同一私有资料库中存在所引用的固定版本；跨站迁移应使用完整数据库及原档备份。
- 案卷草稿仅在当前页面内存中；没有自动保存承诺。导出用于离线保留，离开提示防止误丢。
- 程序部署前需在原站点应用新增的 `0003_research_journal.sql`。缺少迁移时只读／导出仍可用，保存明确不可用；服务端不会偷偷建表。
