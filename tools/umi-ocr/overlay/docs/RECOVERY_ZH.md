# 第二轮：断点续跑与失败重试

## 使用方法

在“批量图片”或“批量文档”的“批量任务”设置中，开启“继续上次任务”，再开始识别。首次开启会记录结果；中断、停止或关闭程序后，重新导入相同文件并开启该选项，即可继续。

图片需保持相同文件列表和顺序；单个文档需保持相同路径、页范围和识别设置。已成功的项目（包括无字页）直接恢复，失败、识别不完整和未完成项目重新处理一次。界面在复用结果时显示“已恢复”。关闭选项则全部重新识别。

输出文件按当前的保存设置重新构建，不把恢复结果接到旧文件末尾。现有文件名规则仍适用：使用日期占位符通常生成新文件，同名输出沿用覆盖行为。建议保留默认日期占位符。改变输出格式不影响识别结果复用；改变输入列表、页面范围、识别/排版参数或引擎身份会生成不同恢复任务。

## 本地记录

记录在输出目录的 `.umi-recovery` 文件夹，包含源文件路径、页索引、识别文字、文本框、分数、结果时间、逐项状态和尝试次数。格式为 SQLite；原图和模型文件不复制进去。参数进入任务标识前先摘要，不持久化原始参数或文档密码。加密文档重新导入时仍需输入密码。

记录是本地明文。停止所有任务后可删除整个 `.umi-recovery` 文件夹；不会删除原始文件或已导出文件。删除后再运行会重新识别。当前没有自动清理、任务历史面板或输入列表自动恢复。

## 实现约束

| 情况 | 行为 |
| --- | --- |
| 程序异常结束 | 每项结果单独事务提交；下次复用已提交结果，重新处理未提交项 |
| 图片内容改变、文件大小和修改时间相同 | SHA-256 内容校验仍使该项失效 |
| 文档内容改变 | 所有页的来源摘要改变，旧页结果不能复用 |
| 文档在打开后或任务中改变 | 终止并要求重新导入，避免混用不同版本 |
| 引擎、模型、参数或后处理源码改变 | 使用不同任务标识；不复用旧结果 |
| 运行中切换引擎 | 中止该恢复任务；变更过程中取得的结果不缓存为成功 |
| 同一恢复任务同时运行 | 操作系统文件锁拒绝第二个实例；拒绝发生在创建输出器之前 |
| 一页部分图片识别失败但仍有正文 | 保留已提取正文及 error 字段；该页标为可重试，批次报告不完整 |
| 输出写入失败 | 中止并显示错误；成功识别结果保留，可修复目录后重新导出 |
| 执行期间点击暂停或停止 | 当前识别可以完成并存入记录；未交付的结果下次恢复，不重复识别 |
| 缓存内容校验失败 | 重新识别该项；数据库整体损坏则明确报错，不默默覆盖数据库 |

SQLite 模式版本为1。job 状态为 running/completed/incomplete/failed/stopped，item 状态为 pending/running/done/failed。job 状态描述识别流程，导出器结束阶段的异常另由界面报告。锁保持到导出器结束处理完毕。

引擎身份覆盖本地插件目录中的代码/模型、设置中明确指向的外部文件或目录、全局和局部识别参数摘要、后处理源码、任务源码、Python/Pillow/PyMuPDF 版本。插件之外且没有在设置中声明的模型、共享引擎运行库和远端模型版本不保证可检测；这些接入方式应关闭恢复，待插件提供明确模型身份后支持。链接模型目录当前明确拒绝恢复。任务运行期间应保持模型文件不变；直接覆盖已加载权重不是本轮支持的热更新方式。

指纹在后台工作线程计算；首次读取较大模型文件可能花费时间，本轮没有性能提升百分比。PDF按打开时的文件签名检查任务期间修改，重新启动时重算内容摘要；不是对抗外部进程同时恶意改写文件的事务快照。

此机制接入桌面批量任务。截图、预览和HTTP上传流程不会自动创建恢复记录。没有新增下载模型、上传文件或云端调用。
