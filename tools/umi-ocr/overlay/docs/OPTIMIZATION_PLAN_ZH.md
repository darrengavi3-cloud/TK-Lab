# Umi-OCR 优化方案与第一轮实现

研究日期：2026-09-13。源码基线：83173efc4f4453b41223ea96d63d44534bf0505c。

## 产品目标

以现有 Python / Qt QML 桌面程序与插件体系为基础，保留离线、便携、截图快速识别，增强长文档处理和结果校对。暂不重写为网页应用。默认本地处理；云端识别应由用户主动选择，并清楚显示传输范围。

现有能力包括截图、批量图片、PDF 与双层 PDF、二维码、公式识别、多栏/竖排后处理、忽略区域、命令行和 HTTP API。它们不是待开发功能。竖排排序不等于所有引擎均能识别竖排文字。当前未进行真实样本识别，不评价准确率高低。

## 推荐交互

保留“截图识别”的快速流程。“文档校对”采用左侧页缩略图、中间原图、右侧文本；选中文字定位到原图文本框。疑字提示使用颜色和图标，不能只依靠颜色。页级状态区分未处理、识别完成、待校对、人工确认与失败，识别完成不得等同于已校对。

批量任务显示完成页数、失败页数、可重试页数。用户可以只重试失败页或选定区域。引擎、语言、竖排设置和输出模板保存为可复用预设。高级模型、预处理和 API 设置进入对应设置页。

## 第一轮代码审计与修改

`UmiOCR-data/py_src/ocr/output/output_csv.py` 原先将所有行和拼接正文保存在内存，直到 onEnd 才写 CSV。编码探测仅覆盖正文，文件名/路径含其他字符时可能写出失败。“忽略空白”原先跳过所有非100状态，包括错误。

现已改为 UTF-8 BOM 表头、逐条追加并关闭文件，保持 Name/OCR/Path 三列与原文字内容。只有101空白状态受 ignoreBlank 控制。结束回调沿用基类空操作，不再重写文件。内存不再随累计导出文本增长；本轮未做性能基准。

测试命令：`python -m unittest discover -s tests -v`。

6项测试通过：多语言及CSV转义往返；空白过滤但保留失败；允许空白输出；结束回调前已有100条结果且重复结束不重写；初始化表头；磁盘写入失败报告。测试使用真实导出器、基类及文本拼接函数，仅替代桌面打开文件接口，不需要Qt和模型。

限制：逐条关闭文件降低程序异常退出时的整批丢失风险，不保证断电持久性，也不是完整断点续跑；沿用同名输出初始化覆盖行为。CSV编码变化可能影响依赖旧本地编码的脚本，需按UTF-8读取。没有执行真实Excel、Qt桌面、引擎推理、Windows/Linux发行包验收。本次仅完成第一轮源码优化，尚非完整升级版安装包。未向上游提交或发布。
