# 第三轮：原图证据与 Codex 辅助校对

日期：2026-09-13。基于上游提交 `83173efc4f4453b41223ea96d63d44534bf0505c`，保留原有 Python / Qt QML 和离线引擎。此轮是源码改进，尚未生成桌面安装包。

## 优先改进的地方

1. **结果可追溯**：把引擎原始文字、后处理文字和校订稿分开；过滤、合并与修订不应抹掉原始依据。
2. **错误可发现**：低置信度、缺失分数、空白、部分识别失败和过滤前后块数变化进入待检查清单。高置信度也不代表正确。
3. **Codex 视觉对照**：提供完整页图、疑字裁图、稳定文本块编号和结构化建议格式，降低来回寻找原图的成本。
4. **长任务可靠性**：沿用第二轮的输入/引擎指纹、断点恢复、失败重试和逐结果导出。
5. **古籍完整性**：保留繁体、异体字、夹注、反切和原注；看不清不补文。后续再加入阅读顺序修订、双页拆分和版面插件。
6. **实测后升级模型**：建立固定截图、扫描件、竖排、夹注、表格样本，分别比较字符错误、漏块、阅读顺序、耗时和内存；没有实测前不承诺准确率提升。

具体借鉴对象及采用边界见 [优化方案](OPTIMIZATION_PLAN_ZH.md)。本轮复用现有引擎，借鉴文档处理的“整页渲染—局部检查—保留证据”流程，没有复制其他项目实现。

## Codex 在这里做什么

Codex/视觉模型可以阅读用户提供的图片，辅助发现 OCR 与字形不一致的地方；这不是一个可嵌入 Umi-OCR 的免费离线“Codex OCR 引擎”。本实现不调用模型、不上传文件、不读取账户或 API 密钥。由使用者主动把待校材料交给支持看图的 Codex 会话，再选择要采纳的建议。

视觉模型仍可能误读小字、旋转文本和非拉丁文字，不能直接作为最终校定依据，见 [OpenAI 图像与视觉文档](https://developers.openai.com/api/docs/guides/images-vision)。Codex 的图像输入方式见 [官方 Codex CLI 文档](https://learn.chatgpt.com/docs/codex/cli)。本机没有 Codex CLI，未验证自动调用；此轮也没有自动调用功能。

## 使用方法

1. 使用本分支完整源码和上游相应运行环境启动桌面程序。在“批量图片”或“批量文档”的“保存文件类型”中选中 **校对包（原图与疑字）**。此选项默认关闭。
2. 开始识别。输出目录会新增唯一的 `文件名.review-随机串` 文件夹；再次运行生成另一份，已有校订稿保留。
3. 在完整源码根目录执行 `python dev-tools/review_cli.py inspect "校对包路径"`，验证证据及图片，并查看每页的 digest 和疑点。
4. 向支持看图的 Codex 会话提供 `PROMPT.md`、`manifest.json`、待核页的 `page.json`、`page.png` 和需要的 `crops/` 图片。必须要求先看全页；漏检文字可能根本没有裁图。按 PROMPT 输出 `proposal.json`，检查每项建议及理由。
5. 明确选中建议 ID 后导入。例如只采纳第一页的 `s1` 和 `s3`：

```bash
python dev-tools/review_cli.py apply "校对包路径" --page p000001 --proposal proposal.json --accept s1 --accept s3
```

生成 `editions/p000001-随机串/edition.json` 和 `text.txt`。每次另存，原图、原始文字和处理后文字不修改。不提供“默认全部采纳”；缺少显式选择、页摘要过期、原文不匹配或图片已变更会拒绝导入。JSON 中保存采纳理由和 unresolved。撤销可回到原始证据或保留的其他版本；尚无桌面逐字撤销按钮。

CLI 校验/导入仅需 Python 3.8+ 标准库；桌面导出还使用项目已有的 Pillow / PyMuPDF。可在没有 Qt 和 OCR 模型的机器上检查与导入已导出的校对包。

## 数据与状态

- `manifest.json`：页顺序、页文件摘要、预期页数；`export_complete` 仅表示全部预期项目已写出，**不是识别成功或校对通过**。取消/导出失败可能留下不完整目录，未列入清单的文件不作有效证据使用。
- `page.json/raw`：图片为后处理前的引擎返回；文档为页级过滤前文本块，`image_results` 另存图像引擎原始返回和到页坐标的变换。PDF 原有文字标记为 `from: text`，不能将它的 1 分当成模型确信。
- `page.json/processed`：现有排版/过滤后的结果；旧的 CSV、JSONL 和文字输出仍沿用处理后结果。
- `page.png`：图片原像素视图或文档页渲染；源文件 SHA-256 与渲染 SHA-256 可追溯。默认不在校对包记入源文件绝对路径，但正文/引擎错误本身可能含敏感内容。
- `quality`：固定 0.85 为初始筛查阈值，未做跨引擎校准。低分和未知分数、无文字、缺失几何信息等标记均不删除文字；普通未标记页面也只叫 `unreviewed`。
- `crops/`：每页最多 200 个有有效坐标的疑点，含 12 像素上下文。超出上限或不能对齐的疑点计入 `uncropped_findings`，仍须检查完整页。
- `editions/`：只有显式采纳的改动写入新版本，状态为 `partially_reviewed`；未修改文字依然未核定。块序按原始证据，不自行重排阅读顺序。

摘要用于发现版本错配和意外修改，并非数字签名：同时篡改清单和文件的人仍能重算摘要。

## 资源与兼容边界

导出默认关闭，开启后会增加图片渲染、原始数据复制、文件校验、磁盘和缓存用量。PDF 以最多 2 倍缩放、最长边不超过约 4096 像素渲染；图片保持原像素，巨大图片可能耗费较多内存。当前每次页导出都会核对完整源文件摘要，大 PDF 的校对包导出会有额外 I/O；尚未做规模性能基准。

带 EXIF 方向的图片暂不自动推断引擎的旋转行为：保留图像、提示需核对方向并禁用可能错位的裁图。图像损坏、源文件改变或渲染失败会明确报告导出失败，不伪造校对图。高分漏字、表格结构、复杂夹注和阅读顺序仍需全页检查。

缺失/非法置信度的平均值不再使识别报错：顶层旧数字字段 `score` 使用 `-1` 表示未知，并新增 `scoreKnown: false`；桌面批量列表显示“置信度未知”。外部消费方应将负数视为不可用，不能当作真实低分。已知分数的行为保持；单栏代码合并无法得到有效平均分时使用 `null`。

校对开关和处理代码已计入恢复参数身份，不能把未保存原始结果的旧缓存当作校对证据复用。校对包不包含实时 Qt 校对编辑器、自动模型调用或跨引擎投票，这些属于后续阶段。
