## 计分方法与限制

- 按 Unicode 码点计算替换、删除、插入；只去空白，不做繁简转换、异体合并或标点删除。
- 预测框与固定标注区域按预测框覆盖比例匹配，阈值 50%，允许多个预测框属于同一标注区域。区域内保留引擎顺序。未匹配文字计插入，完全未检出区域全部计删除。
- 阅读顺序独立统计不同标注区域之间的预测块逆序对、覆盖率和交错次数。单区域样本没有可比较对时报告 `null`，不能记作“顺序正确”。段落内部的顺序错误仍会增加 CER；这不是字形错误的纯估计。报告也保留未经区域重组的序列编辑数。
- 比较顺序错误率时同时看覆盖率；漏检会减少可比较对，不能因此宣称顺序更好。完整逐例计数见 [v4](reports/v4-mobile.json) 与 [v6](reports/v6-small.json)。
- 耗时是单次测量，不是 P95。峰值为 Linux `ru_maxrss`，包含模型启动；不包含 Qt 主进程。环境为 x86_64 / Intel Xeon Platinum 8573C，RapidOCR 3.9.2、ONNX Runtime 1.23.2，算子线程 2、跨算子线程 1。工作进程均开启 Linux 内核断网验证。
- 公共数据标注可能有字形或分段误差，尚未经过第二位古籍专家逐字复核。后续纠正真值必须保留旧版本和原因，不得只修正对某模型不利的部分。新用户资料应另设保留集，不回用于调参。
- 尚不覆盖手写、破损残页、超长批次、复杂跨页表格及 Windows 性能。
