# 观史台 UI 设计契约（V56）

## 视觉方向

观史台是面向史料审校的工作台，不做仿古装饰模拟。V54 的视觉母题是“兰台案牍”：顶部模块像案卷脊签，检索是固定的案头入口，证据状态先于装饰。页面先让用户看懂模块、序位和证据状态，再提供细节编辑。

## 版式规则

- 模块页使用宽内容列，标题、说明和工具栏保持同一左边界。
- 人物记固定为左侧“人物档案／时期快照”双入口；卡片点击只进入人物详情，卡片内不嵌套第二个跳转动作。
- 检索工具栏保留一个主输入框，筛选条件从常用到高级逐级展开。
- 全站只有一个固定“检索”入口；模块内使用“打开统一检索”动作，不再复制检索输入框。
- 政权色只表达政权；文官、武官、州府、军府使用标签和结构，不用随机颜色替代证据分类。
- 立绘是界面识别资产，必须有 `interfaceOnly` 或同等说明，不得暗示为史实肖像。

## 组件状态

按钮、输入框、卡片和抽屉必须具备默认、悬停、键盘焦点、禁用/忙碌和移动端状态。颜色不是唯一状态提示；“待考”同时显示文字。

## V50 设计决定

- 将军名号按曹魏、季汉、孙吴、西晋分别列出；曹魏/西晋按官品，季汉/孙吴按制度序列。疑难杂号保留“待考”。
- 人物立绘首批 50 人优先君主、公卿和军政核心；每张设计稿必须有可辨识五官，但仍标记为界面识别资产，不作为历史肖像复原。
- 未导出生产资源的 Figma 设计稿不得回退显示无五官占位图；人物卡只显示已有人脸生产资源，其他条目标注“立绘设计待同步”或“未生成”。
- 人物统计改为单行紧凑指标带，避免统计卡片在宽屏形成第二行大面积空白；模块品牌统一为“观史台”。

## V51 设计决定

- 全站视觉统一为“史料工作台”：纸张灰底、墨色正文、朱印操作、金色证据提示；不使用强仿古纹理。
- 顶部导航、工具栏、卡片、表格和抽屉采用同一套细边界与低阴影规则，信息层级优先于装饰。
- 人物记不再显示版本设计板和立绘数量状态行；人物卡只呈现人物资料与已接入立绘。
- 所有新增立绘均为带五官的界面识别资产，并标记 `interfaceOnly`，不作为史实肖像证据。

## V54 设计决定

- 主题提供“兰台清昼”“朱批纸本”“青灯夜校”三套语义令牌；政权色不随主题改变。
- 密度提供“舒展／紧凑”，动效提供“标准／减少动效”；偏好只保存为小型界面设置，不进入工程 JSON。
- 按钮分为朱印主按钮、墨线次按钮、轻量幽灵按钮和危险按钮；图标按钮必须有可见焦点和无障碍名称。
- 模块切换、抽屉、卡片只使用有语义的短动效；系统或用户选择减少动效时取消位移、交错和缩放。
- 运行时令牌由 `index.html` 中的 `--v54-*` 变量负责，`DESIGN.md` 是已接受值与语义说明的镜像；主题选择器通过 `data-sgz-theme` 映射到同一套语义令牌。

## V54 反面清单

- 不使用厚重仿古纹理、随机渐变、无限循环动画或 emoji 作为核心工具图标。
- 不用颜色单独表达“待考”、文武属性或证据状态。
- 不把同品官职强行排成未经史料支持的绝对尊卑序列。

## V57 统一检索与史料净化

- 顶栏只保留“检索”、阅读／审校和“外观”；模块不再渲染“检索本页”或第二个文本检索框。
- “外观”采用约 288px 的锚定浮层，控制主题、密度和动效；控件使用 12—13px 系统无衬线，品牌、人物名和史料标题才使用宋体。
- 职官谱前台只保留“朝堂／表格”；树形、横向思维导图、缩放工具和 GoJS 运行时退出读者界面。朝堂选中的官位在审校模式打开对应数据案卷。
- 食货志为制度、编年、户口物价三个互斥视图；金石录不在读者界面显示档案层级和核心／扩展／争议徽标。
- 证据状态与工作流状态分离：`evidenceStatus`、`reviewState`、`uncertaintyReason`、`readerVisibility` 由研究模型统一迁移，阅读模式不显示工作流词。
- 人物索引只以稳定 `personId` 合并；非人物、地名、官名、民族名和 OCR 残片从活动源移除，立绘资产与人物实体审计分离。

## V62 五朝人物与金石阅读层

- `assets/ui/v62.css` 是非地图模块的最终覆盖层；不得改写形势图 iframe 内的几何、图层、时期和配色。
- 人物记常驻检索是对 V57 “模块内无平行检索”的唯一例外，范围严格限定为人物全量名录；顶栏统一检索仍负责跨模块跳转。
- 后汉、魏、季汉、吴、西晋标签始终按王朝顺序显示；历史集团和部族归属使用次级文本，不制造额外主色标签。
- 官职、爵位和金石目录的读者题名只显示纯净 `displayTitle`；阶段、别名、类型和原始题名进入独立字段，不堆叠在标题括号中。
- 金石阅读区使用约 40—44 个汉字的正文宽度、稳定宋体行距和清晰章节间隔；残字、补字和原行款不得因排版清洗而改变。
- 275 个立绘组件均为界面识别资产。图内不加入姓名、印章、水印或史实复原暗示，人物详情保留统一资产边界说明。

## V63 字段发布门禁

- 读者态以 `SGZ_V63_READER_PEOPLE` 为人物标量与标签的唯一入口；未进入读者投影的表字、籍贯、生卒、传记、别名和历史归属不从运行时候选数据回填。
- 任官和封爵只按读者投影中的 `appointmentIds` 与 `peerageEventIds` 取值；多人共用封爵事件仍以 `eventId@personId` 隔离，不因同事件串档。
- 审校台账、工作簿行号、检索日志和本机路径不进入读者包。证据案卷在读者态不仅隐藏内容，也不占用布局宽度。
- 数据文本只作为文本节点或已转义的地图标签渲染，不使用可执行 HTML 注入作为高亮、图表或详情容器。

## V64 前端收口

- 运行时样式固定为 `tokens.css` 、`base.css` 、`components.css` 、`modules.css` 、`responsive.css` 五层；V55—V62 版本样式只作历史档案，不再并行参与级联。
- 首屏只载入壳层和持久化模块。人物、州镇、金石数据与交互逻辑按首次进入加载；战事、食货和地图资源同样不进入非相关模块首屏。
- 模块、人物、碑刻、筛选和地图时期都以稳定 ID 写入 URL，浏览器刷新、前进与后退可恢复同一界面状态；文档标题随当前模块和详情更新。
- 移动“全部模块”使用真正的模态对话框：Tab 焦点留在弹层内，Escape 关闭，关闭后返回原触发按钮。
- 持久化以增量 patch 作为撤销、重做和自动保存的常规单位。只有显式命名版本与较长周期检查点生成整库快照；无变更时不写入、不生成新历史项。

## V66 职官、人物、州镇与战事纠错

- 外观设置只有一个锚定浮层；主题、密度与减少动效共用该浮层，不再保留抽屉或第二套外观面板。
- 职官朝堂以稳定语义 ID 与政权内序位渲染。曹魏中书监、中书令、中书侍郎、通事郎分别占位；武官先按中枢统军、禁军、方镇将军、中郎将、校尉、都尉等制度类别分组，再按政权内规范次序排列，不跨政权强行套用同一品级。
- 曹魏爵制节点使用 `peerage:wei:*` 语义 ID。爵位节点显示已关联事件和受爵人物，人物封爵时间线可反向定位；后汉沿革、年份未明与审校待定事件不混入曹魏本朝统计。
- 人物记只呈现统一人物注册表。V60、260 年表和曹魏封爵表是后台来源，不成为前台数据集、筛选项或 URL 状态。
- 州镇任职事实与治所字段采用独立门禁。读者投影保留所有通过 V65 任职门禁的记录；治所只有在有效年代、来源、定位和摘录同时完整时才附加显示，无法唯一确定时省略该字段且不显示占位。州治、军府驻地与人物实际驻地继续分别建模。
- 战事纪使用单根编年导线与汉末、三国、西晋三个滚动锚点。锚点只定位、不筛选；类别、交战关系、时期、交战方、战役链和局部密度控件不再出现。详情只提供中性的上一条、下一条与独立地图动作。

## V66 后汉百官志结构图

- 后汉朝堂使用专属呈现投影，不改写通用 `courtHierarchy`，魏、季汉、吴与西晋继续使用既有朝堂模板。
- 结构图固定保留皇帝、中枢与公位主图；九卿、台阁近侍、军职宿卫、东宫、地方行政一次只展开一个专题，避免把整部官制铺成超长静态树。
- 皇帝是不可操作的结构节点；太子作为东宫侧翼，不置于皇帝至三公的纵向连线上。太傅、三公与大将军按 1—3—1 的制度并列顺序展示。
- 礼制、宫卫、治政等只表示阅读分组，不写回正式隶属关系。未具备规范节点的符节台、中宫、京师军卫和九卿属署不得由界面臆造。
- 全站统一检索仍是职官检索的唯一入口；后汉结构图不设置第二个文本检索框。
- 桌面阅读态使用专题导航、主图、官职详情三栏；审校态让位给既有证据案卷。760px 以下官位详情为全屏对话框，支持 Escape、焦点圈定与焦点恢复。

## V67 州镇表与金石录双卷工作台

- V67 保留全站卷脊、顶栏和上下文栏，只在州镇表与金石录内容区使用“墨色题签＋纸本案卷”。墨色题签不承担第二套全站导航；政权、材料类型等筛选仍归上下文栏所有。
- 桌面州镇表使用“辖区索引／职任表／记录案卷”三栏。辖区数量从当前读者投影动态生成；职任表固定展示辖区、政权、人物、职任、已核治所、任期和记录类型；案卷下方只在存在数据时显示已核治所分期和相关历任长官。
- 州治、郡治、军府驻地和人物驻地保留各自类型，不互相替代。任职已经发布但治所未通过门禁时，省略治所字段，不显示“治所未详”或空表。
- 桌面金石录使用“分页目录／阅读案卷”双栏。目录每页十二条，显示规范碑名、时代、材料类型和已确认地点；案卷按题名、媒体、基本资料、释文、内容摘要和关联信息组织。
- 金石媒体只消费 `mediaAssets[]` 中 `publicationStatus=verified`、具有本地路径和替代文字的资产。无合格媒体时不创建图片节点或图片区占位；来源、许可和使用边界只在已核资产中随图展示。
- 释文必须保留原行款、章节、换行及缺字符号，正文阅读宽度控制在约四十至四十四个汉字。检索命中使用转义后的文本片段与原生 `mark`，不得使用 `v-html` 或原始 `innerHTML`。
- 980px 以下列表与详情分离，详情使用全屏抽屉；桌面每个索引、目录和阅读区各自只拥有一个明确滚动容器。所有记录按钮、分页和前后导航具有原生键盘语义与清晰焦点。
- 州镇筛选、页码和记录 ID，以及金石时代、材料、政权、页码和记录 ID，均写入 URL；刷新、前进、后退和分享应恢复同一案卷状态。

## V68 人物小传与州／方镇分层

- 人物详情把已有可公开传记字段放入独立“人物小传”卡片；没有已核小传时整块不渲染，不使用占位文字，也不把审校来源带入阅读态。
- 州镇表将辖区层级作为显式筛选，分为“州”与“方镇”。州数说明采用现有东汉十三州、曹魏十二州、季汉益州一州、孙吴四州域及西晋十九州基准，不以当前任职记录数量冒充行政区总数。
- 后汉与季汉使用独立档案标签；同一底层 `polity=汉` 记录仅在已有稳定键或明确年代支持时归入对应标签，无法拆分者保留中性“汉”。
- 左侧辖区索引按“州／方镇”分组，州数只作为现有政权基准标签，不把当前公开任职记录数冒充完整行政区清单。
