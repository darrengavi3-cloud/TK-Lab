# V53 本地缓存配额修复

## 根因

旧逻辑把完整工程 JSON 写入 `localStorage`，同时还可能保存完整上一版快照和完整独立存档。用户上传的本地立绘以 data URL 进入工程 JSON 后，重复副本会迅速超过浏览器配额，最终在写入 `sgz_zhiguanpu_project` 时抛出 `QuotaExceededError`。

## 修复

- 完整工程、最近快照和独立存档改存 IndexedDB `sgz_zhiguanpu_cache_v2`。
- `localStorage` 仅保存后端指针、哈希和字节数等小型元数据。
- 首次打开时兼容读取旧的主缓存、快照和独立存档；写入 IndexedDB 后读回校验哈希，再清理项目自己的旧副本。
- IndexedDB 不可用时退回 localStorage，但不再写入完整快照和保存环。
- 配额错误显示工程大小和可恢复提示；提供“清理旧缓存副本”入口，不自动删除导出文件或 IndexedDB 当前工程。
- `exports/三国职官谱-单文件版.html` 使用同一套缓存逻辑。

## 验证

- `node scripts/verify-project.mjs`
- `node scripts/verify-research-model.mjs`
- `node scripts/verify-map-data.mjs`
- `node scripts/verify-historical-model.mjs`
- 浏览器本地预览：无控制台错误，状态显示已缓存至 IndexedDB。
