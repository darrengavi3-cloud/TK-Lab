# V64 版本化迁移清单

## 结论

`sources.lock.json` 只记录哈希，不包含规范源内容。如果 Site Git 只提交构建代码，而规范源仍留在非 Git 兄弟目录，那么部署的 `commit_sha` 无法重建实际读者包。因此，完成下述迁移前不应将 V64 视为可追溯发布。

## 目标结构

```text
site-repository/
├── atlas/                 # 版本化规范源，唯一可编辑数据源
│   ├── assets/
│   ├── data/
│   ├── scripts/
│   ├── docs/
│   ├── index.html
│   ├── DESIGN.md
│   ├── UX-CONTRACT.md
│   └── sources.lock.json
├── app/                   # Site 壳层
├── public/legacy/         # 由 reader-bundle.json 单向生成
└── .openai/hosting.json
```

## 人工迁移步骤

以下路径固定为：

- Site Git：`/Users/bobiaisi01/Documents/中华三国志优化/三国职官谱私密网站`
- 现规范源：`/Users/bobiaisi01/Documents/中华三国志优化/三国职官谱项目`
- 迁移后规范源：`/Users/bobiaisi01/Documents/中华三国志优化/三国职官谱私密网站/atlas`

### A. 保留旧 Git 历史并建立 `atlas/`

1. 等所有并行代理结束并通过最后一次 `release-check`，记录 `sources.lock.json`、`reader-bundle.json` 和 `deployment-manifest.json` 的聚合哈希。
2. Site 当前已把旧 `public/legacy` 和 `public/三国职官谱 .html` 暂存为删除。先用 `git archive --format=tar -o /tmp/观史台-public-legacy-pre-atlas-20260830.tar HEAD -- public/legacy 'public/三国职官谱 .html'` 保存一份只读 Git 备份，再只执行 `git restore --staged -- public/legacy` 和 `git restore --source=HEAD --worktree -- public/legacy`。不得恢复或覆盖 Site 的其他未提交修改。
3. 使用 `git mv public/legacy atlas`，让旧镜像的文件历史跟随到 `atlas/`；旧大单页继续保持删除，不进入 `atlas`。
4. 在临时目录中只装入当前规范源的 `assets/`、`data/`、`scripts/`、`docs/`、`index.html`、`DESIGN.md`、`DEV_STATE.md`、`README.md`、`UX-CONTRACT.md` 和 `sources.lock.json`，再以该临时目录单向覆盖 `atlas/`。不复制 `backups/`、`exports/`、`templates/`、个人附件、缓存、临时目录或任何 Site 生成物。覆盖前保留第2步 Git 归档，因此旧镜像中的过时文件可以安全删除。
5. 检查 `git status --short`：规范文件应表现为从 `public/legacy` 到 `atlas` 的重命名或更新；`git ls-files public/legacy` 必须为空，`git ls-files atlas/sources.lock.json` 必须恰有一项。

### B. 把 Site 构建改为只从 `atlas/` 重建

1. `scripts/sync-reader-bundle.mjs` 的 `canonicalRoot` 改为 `path.join(siteRoot, 'atlas')`，不再读取相邻目录 `../三国职官谱项目`。
2. `package.json` 增加 `build:atlas`：`node atlas/scripts/build-all.mjs`；`build` 在 `vinext build` 前依次执行 `build:atlas` 和 `sync:reader`。这样干净克隆中即使没有 `atlas/exports/`，也会先从同一提交重建读者包。
3. `release:check` 改为 `node atlas/scripts/release-check.mjs && npm run sync:reader && npm run lint && npm test`。站点发布、测试和本地同步均不得再出现兄弟目录路径。
4. 保留忽略项 `/atlas/backups/`、`/atlas/exports/`、`/atlas/node_modules/`、`/atlas/public/`、`/public/legacy/` 和 `/public/三国职官谱 .html`。`public/legacy` 只能由 `reader-bundle.json` 同步生成，不提交、不手改。
5. 用 `rg '三国职官谱项目|\.\./.*atlas' package.json scripts tests README.md` 检查旧兄弟路径；结果不得再包含构建或同步依赖。`.openai/hosting.json` 和 owner-only 项目 ID 不改。

### C. 提交前重建与哈希核对

1. 从 Site 根执行 `npm run release:check`，确认 `atlas` 连续两次重建哈希一致、读者泄露扫描通过、Site 剪枝后清单闭合。
2. 确认 `release-metadata/canonical-sources.lock.json` 与 `atlas/sources.lock.json` 字节一致，`release-metadata/reader-bundle.json` 与最新读者清单一致。
3. 提交 `atlas/`、Site 壳层、同步脚本、测试、锁文件与说明；不得提交 `atlas/exports/`、`public/legacy/`、离线 ZIP 或轻量单 HTML。部署的 `commit_sha` 必须指向这一提交，才能由 Git 内容独立重建线上读者包。
4. 提交前再次检查暂存区，确保没有本机绝对路径、外部 Excel、`backups/`、`exports/` 或访问凭据。

### D. 保留原规范路径为兼容链接

1. 只有在 Site Git 内的 `release-check` 与哈希核对通过、所有代理停止写入后，才执行此步骤；需另行确认，因为它会改动现有 2.2GB 目录路径。
2. 先把原目录原子改名为同级只读备份，例如 `三国职官谱项目.pre-atlas-20260830`，不得直接删除。
3. 再建立兼容符号链接：`三国职官谱项目 -> 三国职官谱私密网站/atlas`。用 `readlink`、规范路径与兼容路径各运行一次只读验证，确认输入锁、读者包和部署清单哈希一致。
4. 备份至少保留到一次 owner-only 站点发布和回归完成；其后是否清理由用户单独决定。本轮不执行目录改名、链接创建或备份删除。

## 外部工作簿

三份 Excel 是可选重生输入，不进入 Git。使用以下任一方式提供：

- `--v60-workbook`、`--v61-snapshot-workbook`、`--v61-peerage-workbook`；
- `SGZ_V60_WORKBOOK`、`SGZ_V61_SNAPSHOT_WORKBOOK`、`SGZ_V61_PEERAGE_WORKBOOK`。

附件可用时，构建先核对 `sources.lock.json` 中的逻辑路径哈希，再重生 V60/V61。附件不可用时，构建保留锁中 `external-inputs/*` 的元数据，并使用 Git 内已提交、同样受输入锁保护的 V60/V61 生成结果。这样干净克隆不需要本机绝对路径也能重建。
