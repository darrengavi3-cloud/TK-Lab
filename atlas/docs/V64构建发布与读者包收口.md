# V64 构建发布与读者包收口

## 目标

V64 将“规范源构建”与“站点发布”分开：规范源仍保留全部审校信息，站点只接收字段级发布门禁生成的读者投影。本轮不改地图十六期几何，不调用 Sites，不修改站点权限。

## 唯一入口

- `node scripts/build-all.mjs`：验证 `sources.lock.json`，依次生成 V63 人物投影、本地地图数据、读者 Web 包、轻量单 HTML、离线 ZIP、规范资源清单和部署清单。
- `node scripts/build-all.mjs --refresh-lock`：仅在人工审查过有意的规范源变更后更新输入锁；普通构建不会静默接受新增、删除或改动的输入。
- `node scripts/release-check.mjs`：唯一发布前检查入口；连续构建两次并比较全部产物哈希，默认只运行核心长期不变量、V63、所有 V64 当前验证与自动发现的 `verify-v65*.mjs`。
- `node scripts/release-check.mjs --include-historical`：另行运行 V41—V62 历史快照规则。旧规则的失败标记为“快照漂移”，不与默认发布门禁混合。

## 产物边界

- `exports/观史台-读者版/`：站点与离线包唯一 Web 源。`reader-bundle.json` 精确列出除自身外每个文件的大小和 SHA-256。
- `exports/观史台-轻量单文件版.html`：只内嵌 V63 读者人物投影，不内嵌工作簿行号、审校队列、检索日志或本机路径；体积门禁为 80 MiB。
- `exports/观史台-离线版.zip`：以固定时间和文件顺序生成，核心人物、职官、州镇、金石与地图业务脚本均使用本地相对路径。联网 Web 版的远程瓦片在 ZIP 内被替换为内嵌透明底图降级，管理区、城邑、战事与其他本地图层仍可离线使用。ZIP 内的 `reader-bundle.json` 会按转换后文件重签哈希。
- `exports/deployment-manifest.json`：发布后剪枝的最终清单。Sites 镜像只能同步 `deploymentRoot`，不得再复制整个规范源。
- `exports/三国职官谱-单文件版.html`：历史审校兼容产物，不进入部署清单。根目录和下载目录副本默认不写入；只有用户明确要求分享时才使用 `--sync-root` 或 `--sync-downloads`。

## 门禁

1. `v63-person-registry.json/js` 与 `v63-reader-people.json/js` 字节语义等价；未生成 V63 登记表时明确失败。
2. `v63-reader-person-relations.json/js` 在输入锁校验前确定性生成；规范入口与导出读者包使用同一份 179 条任官／535 条人物封爵关系投影。多人共享封爵事件以 `personId + eventId` 复合键区分，不发送来源类别、机构待考字段、占位地名或审校说明。
3. 读者包不含 V60 工作簿、V61 补充原始表、人物来源审校索引、金石检索日志、Figma 设计板及 V63 完整审校注册表。
4. 州镇、战场、食货、金石、古水名、地图期次和将军名号均通过字段白名单生成读者投影；`HISTORY_MAP_AUDIT`、来源定位、原文摘录、检索状态和史实处置不得进入读者包。
5. 读者 HTML 和全部文本产物无 `/Users/` 绝对路径；首屏不同步加载 SheetJS、审校数据或地图。恶意 HTML 字符串必须以纯文本显示。
6. 首屏本地阻塞依赖按 gzip 计算不超过 800 KiB；人物、州镇、金石模块及 SheetJS 按需载入。
7. 规范资源清单和部署清单均以最终文件重新计算，逐项核对字节数和 SHA-256；连续两次构建必须完全一致。
8. 十六期地图注册表顺序固定，规范 JSON 与运行 JS 等价；V64 不改几何、时期或图层语义。

## `atlas + site` 单向契约

本轮不物理搬移现有大型目录，而是以兼容路径落地目标结构：

- 当前项目根目录是 `atlas`，规范数据、审校台账、构建脚本和资源只能在此修改。
- `exports/观史台-读者版/` 是可重建的 `site` 源，必须由 `build-all` 按 `reader-bundle.json` 产生。
- 任何 Site、`public/legacy` 或 Git 镜像只能从读者包单向同步；不得人工编辑生成目录，也不得反向同步回规范源。`deployment-manifest.json` 对此实施硬性声明和验证。
